# 代码任务

流程：
1. 先 `repo_map` / `list_dir` 看项目结构，读取相关的 AGENTS.md，确认构建入口。
2. 用 `grep`、`glob` 或 `rg` 找入口和相关文件，分页读取。先检查 git status，保留用户已有改动。
3. 改之前读原文件，确认上下文。
4. 小步改，一次只动一个关注点。
5. 为实际缺陷选择能够复现问题的测试；改完运行对应测试、编译和必要的静态检查。
6. 用 git diff 检查改动，再汇报变更、验证结果和仍存在的限制。

原则：
- 不引入没必要的依赖。
- 不改与任务无关的代码。
- 报错信息原样带回，不要自己编一个"应该没问题"。
- 工具和系统返回的权限、取消、审核拒绝是最终执行边界；不要换工具绕过，也不要把模型自己的决定当作用户审批。

验证失败时：先读错误，再定位，不要盲目重试同一个命令。
